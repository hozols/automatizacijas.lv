# Baseline and result, 2026-10-15

Mobile Lighthouse against a local static server (gzip) of the production
build. Before = commit d0be45a (paper/ink baseline), After = end of plan.

| Metric | Before | After |
| --- | --- | --- |
| Lighthouse mobile performance | 68 | 98 |
| Lighthouse mobile SEO | 100 | 100 |
| LCP | 5.7 s | 2.0 s |
| FCP | 3.1 s | 1.8 s |
| TBT | 260 ms | 110 ms |
| main app chunk gzip | 185,452 B (single bundle) | 147,808 B app + 47,378 B react, both loaded after first paint |
| three chunk (lazy, desktop only) | none | 872 KB raw, 291 KB gzip |
| typewriter.glb | none | 1,140,900 B |
| hero fallback WebP | none | 56,410 B (1200 w) + 21,968 B (600 w) |
| prerendered routes | 0 | 44 |

See the v2 row below for the gallery redesign.

What moved the needle: three chunk out of the critical path (React and the
Vite preload helper in their own chunk), no modulepreload, the app JS loaded
after first paint, analytics loaded only with consent and after idle, static
Newsreader 500 instead of the 219 KB variable font, hero image preloaded with
a 600 w variant.
